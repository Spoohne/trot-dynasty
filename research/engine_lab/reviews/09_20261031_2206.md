## 1. Highest priority: reject “style is only a report tag” and “position now emerges from ability”

**Code findings:**
- `run()` still gives `"stalk"` a **1.5 ft/s higher opening target** than other non-leavers. The generated label therefore changes behavior.
- Rank imposes nearly the same positional spread whether early-speed differences are tiny or enormous. The slowest horse’s gap is not exactly seven lengths—finish/stamina adjust it—but the rank term strongly prescribes that disadvantage.
- `es.index(e)` gives all tied-fastest horses rank zero: identical horses **all try to lead**, whereas tiny perturbations usually produce one leader.
- Better late speed makes a non-leaver sit farther back **and move later**. **H:** this can penalize an improved horse through its driver policy.
- Explicit `leave` overrides are not propagated consistently: `want_gap`, default move point and reporting label still use the locally computed `lead`.

**Recommendation:** describe this as a **stats-conditioned tactical heuristic**, not emergent positioning. Base the initial plan on attainable opening speed differences, post and expected effort—not rank alone. Keep the plan advisory; actual positions should result from movement and traffic. Do not normalize tiny differences into a full-field positional spread.

## 2. Reject H12’s causal interpretation

**Accept the narrow measurement:** this particular `rate()` favorite wins 15–25% in these sampled fields/settings.

**Reject:** “therefore trip and traffic outweigh ability.”

Reasons:
- Fields are deliberately close: every trait has SD **0.4**. Low favorite success in tightly matched fields says little about class separation.
- `rate()` weights early speed **1.15** versus late speed **0.85**, while the fresh-speed ceiling weights them **0.6 versus 1.6**. Early speed also affects acceleration and tactics; stamina and gait act nonlinearly. Neither formula alone establishes the true favorite.
- Profile mode makes ability alter tactics. A lower win rate could reflect a poor planner, not weak physical ability or excessive randomness.

Also reject **“rank weight 1.0 favors the best horse”**; it favors the legacy rating’s favorite more often in this sample. Do not ask Patrick to choose a favorite-win target from these numbers yet.

## 3. Assay: fair as a package comparison, not a clean mechanism comparison

The same generated horses/posts are a good foundation. But:
- Fixed mode has randomly assigned styles and random move-point offsets; profile mode has deterministic plans. Multiple things change together.
- Identical race seeds do not preserve identical shocks: fixed mode consumes Gaussian draws for move timing; profile mode generally does not, shifting subsequent break draws.
- Reporting categories differ: fixed labels are assigned independently of traits; profile labels are outcomes of the planner. Their win shares are not directly comparable.
- The 300-race rows need **paired uncertainty** against their matching controls. “±3 points” is approximately a maximum **standard error**, not a 95% interval; that interval can be roughly ±6 points.

For isolation, disable breaks and preassign all driver randomness. Retain per-race results and actual profile-specific start counts. Validate at DT 1/16.

## 4. Smallest next experiment: policy-induced ability penalties

First add cheap unit tests: identical traits, tiny early-speed perturbations, explicit leave overrides, and **label invariance with instructions held fixed**. Fix failures before racing.

Then use **20 fixed fields × eight subject-post rotations**, breaks off:

- Improve the subject’s **late speed by +0.5**.
- Compare baseline with the improved horse under:
  1. **Frozen baseline plans for every horse**.
  2. **Recomputed profile plans**.

Log paired subject finish time/place, desired gap, move point, achieved position and boxed time.

**Predeclare the reading:**
- Frozen-plan improvement helps, replanning erases or reverses it → planner penalizes ability.
- Neither helps consistently → inspect physical/traffic response before revising ratings.

This directly tests the most concerning bias with one trait intervention, rather than another broad parameter search.
